# Blue Max — Commander X16

An 8-bit port of the [Blue Max](../README.md) homage in the parent directory,
written from scratch in **65C02 assembly** for the **Commander X16**.

The Three.js version is a 2.5D WebGL game; none of that code carries over. What
carries over is the *design* — the diagonal scroll, altitude read off the gap
between aeroplane and shadow, bombs that have to be led onto the target, fuel
that forces you to find a runway — rebuilt around what VERA actually does.

```
   Output    BLUEMAX.PRG, loads at $0801 with a SYS stub
   CPU       65C02
   Video     VERA — one 64×64 tile layer, 4bpp 16×16 tiles, 55 sprites
   Audio     VERA PSG, 7 voices
   Assets    none: every pixel is generated by tools/gfx.cjs
```

## Controls

| Key | SNES pad | Action |
|-----|----------|--------|
| ← → | D-pad | Steer left / right |
| ↑ ↓ | D-pad | Climb / dive |
| **Z** | B | Machine guns (they overheat — watch the GUNS bar) |
| **X** | A | Drop a bomb |
| **Enter** | START | Start a sortie |

Keys come from the KERNAL's `joystick_get`, so a real SNES controller in port 1
works too — plug it in and pass `-joy1` to the emulator.

## Playing

Fly north-east over scrolling farmland. Your shadow tracks along the ground
underneath you: the further the aeroplane sits above it, the higher you are.

- **Bombs are led, not aimed.** A bomb keeps your velocity and holds its screen
  position while it falls, so the landscape slides underneath it. Drop from high
  up and it lands a long way ahead; drop low and it lands almost immediately.
- **Guns need altitude discipline.** Bullets only bite aircraft at your own
  height, and only strafe ground targets from below 26 units.
- **Fuel runs out.** Runways are the pale strips running *parallel* to your
  flight path. Line up with one, dive onto it, and the ground crew refuels and
  rearms you before you take off again. Touching the ground anywhere else is a
  crash, as is flying into a building.
- **The ground shoots back.** AA guns and tanks throw up flak; enemy aircraft
  converge on you and fire tracers.

## Building

Needs [cc65](https://cc65.github.io/) and, to run it,
[x16-emulator](https://github.com/X16Community/x16-emulator). Node is used only
to regenerate the graphics data.

```powershell
$env:CC65_HOME = 'C:\path\to\cc65'
$env:X16_HOME  = 'C:\path\to\x16emu'
.\tools\build.ps1 -Run
```

Or drive `cl65` directly:

```sh
node tools/gfx.cjs
cl65 -t cx16 -C cx16-asm.cfg -u __EXEHDR__ -I src --bin-include-dir src \
     -o BLUEMAX.PRG src/bluemax.asm
```

On real hardware, copy `BLUEMAX.PRG` to the SD card and `LOAD"BLUEMAX.PRG",8,1`
then `RUN`.

Two assembler defines help when testing without a keyboard:
`--asm-define AUTOSTART` drops straight into a sortie, and `--asm-define DEMO`
synthesises stick input so the game flies, shoots and bombs itself.
`tools/shot.sh` uses both to grab frames out of a headless emulator run.

## How it works

**The diagonal scroll.** `camX` counts up and `camY` counts down by the same
number of pixels each frame, which streams the ground away to the lower left and
makes the aeroplane appear to fly up and to the right. Both counters are 16-bit
and allowed to wrap — 65536 is a whole number of 1024-pixel map widths, so the
wrap is invisible.

**Endless terrain from a 64×64 map.** Only 21×16 tiles are on screen at once, so
there are always 40+ tiles of slack in the wrap. When the camera crosses a tile
boundary exactly one map line changes meaning and is refilled from
`tile_at` — 64 entries, once every 16 pixels of travel. Terrain is a pure
function of world tile coordinates (a two-lookup permutation hash), so nothing
has to be remembered.

Features are placed using two derived coordinates: `S = WX - WY` runs along the
flight axis, so bands of constant `S` *cross* your path — rivers and roads.
`D = WX + WY` runs across it, so bands of constant `D` lie *parallel* to your
path — runways you can line up on. Because flying north-east keeps `camX + camY`
constant, `D` changes only when you steer, which is exactly the "line up with the
strip" mechanic.

**Everything else is a sprite.** Ground targets, aircraft, bullets, bombs, flak
and explosions all live in screen coordinates. Anything anchored to the ground is
drifted by the same `spd` as the tilemap each frame, so it stays welded to the
landscape with no world-coordinate bookkeeping. Sprite attributes are built in a
RAM shadow and pushed to VERA in one burst at vblank.

**The HUD** is a second VERA layer in 1bpp text mode, borrowing the KERNAL's
charset. Cells are written with a background colour of 0, which VERA treats as
transparent, so the text floats over the game.

## Layout

```
src/bluemax.asm    entry point, state machine, main loop, variables
src/vera.inc       hardware definitions
src/video.asm      VERA bring-up and asset upload
src/terrain.asm    the scrolling landscape and its generator
src/sprite.asm     sprite attribute shadow buffer
src/world.asm      targets, enemies, bullets, bombs, flak, explosions
src/player.asm     the aeroplane
src/hud.asm        text overlay
src/sound.asm      PSG driver and the music sequencer
src/data/          generated — do not edit
tools/gfx.cjs      draws every tile, sprite and palette entry
tools/build.ps1    build (and optionally run)
tools/shot.sh      headless screenshot
```

`src/data/` is generated by `tools/gfx.cjs`; it is committed so the project
builds without Node, but edit the generator, not the output.
